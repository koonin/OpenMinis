# 小智通过蓝牙连接小冠

当前实现使用纯蓝牙传输：小智的 Opus 收音、控制消息和小冠的回复音频均通过
BLE GATT 收发。小智不启动 Wi-Fi，不需要热点、IP 地址、配网页或 Mac 桥接。
手机仍需通过自己的蜂窝网络或 Wi-Fi 访问模型及所选云端语音服务。

## 使用方式

1. 小智安装 `ai-passport-openminis-ble` 固件，小冠安装对应版本。
2. 打开小冠「设置 → 小智设备」，开启「连接小智设备」并允许蓝牙。
3. 等待「蓝牙已连接」，按小智 OK，说话并停顿。音色、语速和会话仍在
   这个页面管理。
4. 前台验证后，再锁屏至少一分钟，按 OK 发起新一轮短对话。

云端语音供应商和 API Key 统一在「设置 → 管理 AI 服务商」配置。
小智页面只选择回复模型、音色、语速和试听，已移除重复的「配置云端音色」入口。

这次升级复用已配对手机和设备的随机凭据。固件首次运行把原配网地址中的
凭据迁移到独立 NVS `openminis/ble_token`，之后从该键读取；不启动旧网络
服务，也不擦除原配置。手机保留原 Keychain 数据和会话。
当前支持已有配对的升级，新设备或换手机的纯蓝牙首次配对向导尚未实现。
因此界面移除了会单方面清空凭据的“解除配对”，避免让现有设备无法恢复连接。

## 手机与小智共用角色

进入「设置 → 灵魂 → 角色模板」，搜索名称、性格或语言，也可以按角色类型和
对话语言筛选。点进角色查看介绍，再点「套用到编辑器」。这一步只更新风格与
角色介绍的草稿；返回「灵魂」页保存后，手机聊天与小智对话统一使用这份人设。
既有名称、头像和音色不变；也可以继续编辑自己的角色介绍。

目录依据 2026-10-29 小智控制台配置页的可见内置人设整理，包含 **160 个控制台
角色、39 种语言**，另保留 3 个通用模板。普通话列表的 58 个选项中，55 个有
专属介绍；晓双、晓悠和 Macerio 多语言项只有默认介绍，不作为独立人设加入。
核对全部 76 个语言入口后，排除了共 23 个无专属介绍的音色选项；同名的捷克语/
斯洛伐克语、葡语/西语等角色按语言分别保留。名称/语言组合与可见清单逐项一致。
模板正文是针对小冠共享 SOUL 设置重新编写的简明性格、互动和表达说明，
不是控制台原文镜像，也不自动同步控制台后续变化或账号的自定义角色。

角色和声音相互独立：模板中的「湾湾小何」是人设名称，不会重新加入已清理的
旧版火山音色，也不代表音色服务授权。云端声音仍从小智的「回复音色」选择。

实现复用 `SoulStore.save` / `SystemPromptBuilder.identitySection()`；小智仍通过
正常 `AIChatViewModel` 提交下一轮语音文字，没有第二份设备角色配置。
`SoulRoleTemplate.swift` 是可独立检查的目录与搜索逻辑；`SoulRoleTemplatesView`
负责列表、筛选、预览及套用。检查入口 `scripts/test_soul_role_templates.swift`
覆盖目录数量、唯一 ID、大小写/重音/全角搜索、组合筛选、同名语言变体、
草稿匹配和正文上限。第一版四模板界面已由用户确认「已填入，保存可点」；
完整目录已于 2026-10-30 00:16 完成构建、签名权限校验、原位安装与启动，
日志 `/tmp/xiaozhi-soul-catalogue-install.log`。用户随后确认「可以了」并要求提交推送，
完成本版界面验收；未逐一验证全部角色的实际模型表现。

小智之间的旧连接路径。历史 Mac 桥接脚本保留作历史实验记录，不参与新链路。

## 传输与行为

- 服务 UUID `CB593B10-7314-4885-A545-39F69381BA6E`，B11 为公开身份，
  B14 为设备上行通知，B15 为手机下行写入，B16 为双向身份验证。
- 复用 192 位随机配对秘密。双方通过 HMAC-SHA256 校验随机挑战，每次连接
  派生新会话密钥；音频与控制消息使用 AES-256-GCM，双向使用独立且严格递增
  的计数器，拒绝篡改、重复和缺失消息。秘密不在蓝牙广播或消息中发送。
- ATT 按协商长度分包，带消息编号、偏移和首尾标记；只允许一个有界消息
  重组。Opus 单包不超过 1275 字节，控制消息不超过 8192 字节。
- 固件发送使用独立任务、有界队列和发送窗口；手机按 Core Bluetooth
  背压发送音频，控制写入等待确认。发送堵塞或断线会结束本轮，不重发聊天。
- 音频仍是 16 kHz、单声道、60 ms Opus。保留 VAD、自然语速修复、发送时钟
  和小范围预缓冲；编码不占用手机主线程。
- 配对后蓝牙订阅持续保留。真实新对话请求申请有限后台时间；一轮回复后
  结束逻辑语音通道，保留蓝牙连接。App 锁、会话锁和 Agent 原有确认流程有效。
- 已经交给 Agent 的任务不会因打断/断线而撤销或自动重复提交；请求仍在
  执行时拒绝并发新请求。长任务、强制退出、重启后未首次解锁仍可能需要
  打开小冠，不能承诺无限后台常驻。

## 小智专用回复模型与耗时

在「设置 → 小智设备 → 回复模型」选择已配置的文字模型。只修改小智会话，
不改其他聊天或全局模型组；选择会保留到下一段小智对话。选择时使用该模型
支持的最低思考强度，复杂任务仍可在小智会话中调整。处理中或会话锁定时
不能切换；失效的供应商/凭据会提示，不会静默换模型。

「最近一次等待」显示结束收音到首包蓝牙音频发出的时间，分为识别、模型、
生成声音和播放准备。实际听到声音还包括设备少量缓冲；不含说话及停顿判定。
控制台流式音色的声音耗时计至首包通过校验，其他音色计至合成返回。
保留上一次数据直到下一次首包，避免自动续听或识别失败清空记录；新会话或
App 进程重启会清空，仅记录时长和模型名称，不增加录音/对话日志。

2026-10-29 在实际 iPhone、四个独立测试会话中用相同短句比较：GPT-6-Astra
两次约 8.95/3.96 秒，DeepSeek Flash 约 1.60/1.05 秒。两者请求最低思考强度，
但 Astra 最低仍为低；这是完整答案阶段的时间，不是设备语音总延迟。
已核对真实小智会话选择为 DeepSeek-V4.1-Flash、思考关闭。用户反馈仅换模型
后仍等很久，因此继续优化控制台音频等待，不宣称换模型已经解决全链路延迟。

## 火山直接流式语音

用户已开通火山语音并在手机的 Doubao (Volcano) 供应商保存 API Key。
在「设置 → 小智设备 → 回复音色」选择该供应商已获授权的音色。原「湾湾小何」
使用 `zh_female_wanwanxiaohe_moon_bigtts`、`seed-tts-1.0` 资源；2.0 音色使用
`seed-tts-2.0`。所选音色必须在该火山项目下获得权限，列表不是鉴权证明。

路径：小智收音 → BLE → 小冠识别/生成答案 → 火山直接合成 → BLE → 小智。
火山只收到这轮待朗读文字，不再发送固定触发语音或调用控制台的取答复工具。
设备仍为纯蓝牙，手机独立联网。控制台实验音色保留为可手动选择的路径。

- HTTP 单向流式接口要求 16 kHz 单声道 PCM，逐行解析有界 JSON 和 base64，
  不使用流式 WAV（官方说明它可能包含多段 WAV 头）。
- 整轮复用一个系统 Opus 编码器，网络分片不会刷新编码器或插入新停顿；
  只有服务明确成功结束才刷出编码尾帧。编码运行在串行 actor，BLE 按原
  60 ms 时钟及背压播放，收到首段即可出声。
- 取消、断线、App/会话锁定会结束本轮语音流。错误或缺少结束标记不会
  当作成功；不自动重发付费合成、重交 Agent 请求或悄悄换音色。
- 每轮最多 75 秒请求时间、90 秒 PCM；限制单行/总响应/消息数，拒绝 HTTP
  重定向。Key 仅由手机既有凭据配置读取；不输出密钥、原始错误响应或音频日志。
- 手机试听走同一条 PCM 接收链路，完整成功后返回 WAV 播放；设备通话走
  连续编码后逐包播放。其他聊天/供应商的语音实现不变。
- 修复火山专用域名误用 OpenAI 模型列表查询的 404：使用内置音色目录，
  提示实际可用性以试听为准；精确限定 `openspeech.bytedance.com`，混合型
  聊天/语音供应商仍正常查询其聊天模型。

本轮本地验证：22 项检查通过，覆盖畸形/截断/错误响应、有界解析、PCM 奇数
字节跨片拼接、完整结束判定、消费者取消和下一次显式请求恢复。3 秒合成
波形切成不同长度（含奇数字节）后得到 51 个 Opus 包，与整段连续编码逐字节
一致，并逐包解码为 16 kHz/60 ms。模拟 HTTP 测试未调用付费服务。
新版已原位安装。用户在 default 项目开通语音服务后，确认其他豆包音色可以
试听，旧版「湾湾小何」仍不可用；该音色使用 1.0 资源，不能凭 2.0 开通状态
判断其已获授权。采用可用豆包音色的前台设备测试声音完整连贯，用户报告
总等待 **3.3 秒**、生成声音 **0.6 秒**，对照同一固定短句的控制台基线
**6.8 秒 / 4.5 秒**。这是各一次实机反馈，不是统计均值。用户随后按锁屏至少一分钟步骤
复测，反馈「正常，仍然较短」；锁屏未另报数字，不能把前台 3.3 秒当作锁屏实测值。

音色选择器补充火山 1.0/2.0 标识，并显示当前音色所需的语音服务；沿用
已有音色选择；该显示更新已于 22:20 签名安装并启动。内置目录补充官方
「小何 2.0」，已有供应商启动时自动补齐目录，也可手动刷新；未自动切换，也未单独实测该音色，
不将其冒充原来的湾湾小何。

## 小智控制台音色（实验）

用户已选择尝试小智后台中转，不另外开通火山引擎。小冠「回复音色」新增
**小智控制台音色（实验）**。首次使用前按小智 OK 一次，更新后的固件会在
已认证的加密蓝牙 hello 中传送原设备 MAC 和板卡 UUID；手机将 UUID 与现有
配对匹配后保存到 Keychain。没有原绑定时会提示，不会生成新身份冒充设备。

路径：小智收音 → 蓝牙 → 小冠识别并完成模型答复 → 手机连接小智官方后台
→ 控制台音色 → 手机转换并核对 → 蓝牙 → 小智播放。Mac 不参与实际运行。

这不是独立 TTS API。手机使用原设备身份向官方配置服务查询 WebSocket，
忽略固件更新/MQTT 字段；以官方设备协议注册唯一只读 MCP 工具
`self.openminis.get_reply`，只返回本轮已经完成的答复。短固定语音
“请原样读小冠答复”触发后台调用工具。后台模型仍参与调度和朗读文本生成，
但不能提交新的小冠提示词、运行其他工具或重做 Agent 任务。

设备播放采用逐句校验：每个音频包对应的字幕必须是小冠完整答复的下一段，
仅忽略空格；通过后按原时钟通过 BLE 发送，不等整段收齐。未调用只读工具、
无有效字幕、开场白、改写和异常音频包均不转发；结束时仍检查是否缺句。
后半段异常时可能已经播放了正确的前半段，此时停止且不计为完整成功，
原答复留在小冠，不自动重试或切换声音。此检查依赖后台字幕，并非重新
识别音频；最多 1500 个 60 ms 帧、单轮 75 秒，消费者取消会关闭后台连接。
手机试听仍等全文检查完成才返回 WAV。

云端原始单声道 60 ms Opus 包直接转发，避免二次有损编码；即使源为 24 kHz，
设备仍按 16 kHz 解码（[Opus 解码采样率说明](https://opus-codec.org/docs/opus_api-1.3.1/group__opus__decoder.html)）。
保留 BLE 发送背压和有界预缓冲，不创建无界音频转发任务。

只向后台发送本轮待朗读文字和固定触发语音，不转交原用户录音、聊天历史
或小冠工具权限。连接令牌只存在内存，拒绝重定向，仅接受官方安全连接。
音色和语速跟随 xiaozhi.me 当前设备绑定，须在控制台调整；小冠本地语速
滑块在此选项下隐藏。无需火山账号或额外语音密钥。其他系统/自配云端音色
仍保留为可选项，不会被自动切换。
